# ERPNext

Use namespaced events; keep heavy business rules in Backend SDK tools.

<InfoBox>
Namespace convention: events under <code>erpnext.*</code>. Connectors emit only; FlowRunner stays in Qefro.
</InfoBox>

## Installation

1. Deploy or enable the ERPNext connector service (Qefro connectors monorepo / your fork).
2. Configure credentials (below) and `QEFRO_API_BASE_URL`, `QEFRO_TENANT_ID`, API token.
3. Point external webhooks at the connector public URL (not directly at FlowRunner).
4. In Qefro, declare flows with `trigger.event` matching emitted names — [Event-Driven Triggers](/docs/guides/event-driven-triggers).
5. Sync SDK tools if the connector exposes Backend SDK handlers.

## Authentication

ERPNext site URL + API key/secret.

Store secrets in the connector environment or secret manager — not in flow metadata.

## Events

| Event name | Notes |
| --- | --- |
| `erpnext.sales_order.submitted` | Emit when source system notifies connector |
| `erpnext.issue.opened` | Emit when source system notifies connector |

Envelope fields (idempotency, correlation, TTL): [Event reference](/docs/reference/event-reference).

## Tools

Typical tool surface: **sales order get, issue update**.

Implement as Backend SDK tools or REST Business Tools. Keep PII minimization and least privilege scopes.

## Webhooks

1. Receive provider webhook → verify signature.
2. Normalize payload → `EventEmitter.emit({ name: 'erpnext.…', payload, idempotencyKey })`.
3. Return 2xx quickly; let Qefro dispatch asynchronously.
