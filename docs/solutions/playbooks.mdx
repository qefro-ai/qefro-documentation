# Solution playbooks

Playbooks are **outcome-oriented**: architecture, prerequisites, installation, flows, and troubleshooting.

:::tip Building a solution package?
If you want to *build and publish* a complete business solution (manifest, UI, workflows, connectors), start with [Solution Development](/docs/solutions/overview) instead.
:::

| Solution | Outcome |
| --- | --- |
| [Customer support](/docs/solutions/customer-support) | Cited answers + tools + handoff |
| [WhatsApp commerce](/docs/solutions/whatsapp-commerce) | Sell and support on WhatsApp |
| [Order tracking](/docs/solutions/order-tracking) | “Where is my order?” end-to-end |
| [Abandoned cart](/docs/solutions/abandoned-cart) | Event-triggered cart recovery |
| [Appointment booking](/docs/solutions/appointment-booking) | Schedule with confirmation |
| [Lead qualification](/docs/solutions/lead-qualification) | Qualify and push leads to CRM |
| [Refund automation](/docs/solutions/refund-automation) | Policy + approval + tool |
| [Conversational commerce](/docs/solutions/conversational-commerce) | Browse / buy assisted on chat channels |
